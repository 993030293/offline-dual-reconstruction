# GitHub 发布边界

## 当前建议

继续使用私有仓库。当前同机四录制根入口已经通过，但仍有以下发布边界和未关闭验收门：

1. 项目原创代码尚未确定统一开源许可；
2. 第三方 3DGS 和 PGSR 含研究/非商业限制；
3. 完整源码快照中保留了部分本机绝对路径，以维持与已验收包的逐文件一致性；
4. 本机四录制根入口冷启动已通过，但跨机器运行尚未通过一次真实冷启动验收。
5. 完整研究源码快照保留了四个原始非生产语法遗留；公开仓库应决定是以归档形式保留，还是另附可审计修复补丁。
6. 提交 `f84c7e5` 已从四份原始录制各用一次根入口控制器尝试完成双输出和八个主预览，同机正式完成 4/4；历史失败、预定义子阶段非零结果和数值警告仍保留，不能写成四例零失败。
7. 当前新预览证明本机交互与资产加载可用，但全场景远离采集轨迹的无人机视角仍有模糊、漂浮/拉丝，PGSR 遮挡区仍有局部孔洞与薄边；独立几何精度没有验证。

## 私有仓库可以包含

- 当前候选中的全部文件；
- 源码与补丁清单；
- 不含敏感内容的失败/修复摘要；
- 后续的 issue、里程碑和跨机器迁移记录。
- 不含私有路径的 RA-012 根因、修复和回归摘要。

## 公开仓库前必须处理

- 把本机用户名、Codex 会话路径和 Playwright 绝对路径改为配置项，并记录这一“仅路径适配、不改算法”的差异；
- 决定项目原创代码的许可；
- 复核第三方组件是否允许当前分发方式；
- 确认 Git 历史中从未提交原始数据、凭据、模型、运行证据或机器配置；
- 至少完成一次干净环境的静态验证和最小跨机器运行。
- 保持 `f84c7e5` 四录制正式验收记录、预定义恢复、失败回执和质量边界可追溯；后续代码变更需重新评估是否触发端到端复跑。

## 不进入 Git 历史

原始 MCAP、图像、数据库、标定私密副本、权重、PLY、网格、环境目录、WSL 虚拟磁盘、浏览器缓存、运行日志和带机器进程信息的回执。即使以后删除，Git 历史仍可能保留，所以必须在第一次提交前阻断。
