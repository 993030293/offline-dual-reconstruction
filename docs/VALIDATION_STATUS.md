# 当前验证状态

更新时间：2026-11-10

## 结论

当前提交是**预发布失败基线**，不是稳定发行版，也没有通过四视频交付验收。

- 本机针对本轮修复的 10 项单元回归通过。
- 本机完整离线依赖预检通过，包括真实浏览器启动、长路径动态导入、三份原生质量 DLL 的加载与行为等价检查，以及 Windows/WSL 依赖检查。
- 当前候选四视频冷启动验收在第一份 `c0_july` 录制失败；完成录制数为 0/4。
- 本轮没有生成可验收的 3DGS 或 PGSR 终态和预览；`c1`、`box1`、`box2` 按失败即停规则没有启动。
- 历史 Box1、Box2 或四录制产物不能代替当前提交的新鲜运行证据。
- 算法运行未使用 LLM、VLM、云 API、在线下载或自动改代码。

本轮失败前的候选快照身份为 `d54ac05ce6a59f7e10316e7391a49e1fb1613196015829e24e7c13d39b79ea20`。该值覆盖当时整个候选目录；提交文档和重新生成发布清单后会自然变化。当前算法源码树的稳定身份以 `PUBLICATION_MANIFEST.json` 中的 `candidate_algorithm_source_version` 为准，完整仓库身份以 Git 提交号为准。

## 当前端到端证据

第四次从零运行 `c0_july` 时：

1. 从原始录制解码 8,053 帧；
2. 初始选择 1,157 帧；
3. SfM 注册 1,157/1,157 帧，生成 71,070 个点，平均重投影误差约 0.767 像素；
4. 位姿间隙补帧注册 5/5；
5. 米制阶段加入额外原始候选后共有 1,226 个注册相机；
6. `physical_joint_BA_1` 的正深度恢复遇到 262 个违规观测、49 个点，首个六视图轨迹初始化达到 100 次迭代上限，并产生约 `2.08e9 m` 量级的退化点；算法按合同停止。

这说明“全部图像已注册”和“平均重投影误差较低”并不足以证明米制几何稳定。当前证据更支持：七月录制包含更强的环绕回访，现有视觉图的长距离回访约束不足，导致后续位置先验与视觉几何发生严重冲突。上游回访匹配是候选修复方向，但尚未进入本预发布基线，也尚未完成端到端验收。

## 已排除的伪修复

以下诊断没有被当成通过，也没有进入当前生产入口：

- 将正深度初始化迭代上限从 100 增加到 1,000：49 个点虽均返回有限值，但最大点范数仍约 `2.22e9 m`；
- 使用 Cauchy 损失重复联合 BA：相机半径仍在数百到上千米范围，违规投影持续存在；
- 使用更强的平移先验反复 BA：相机半径可降到约 10 m，但违规投影没有稳定归零，仍不满足原合同。

因此当前不会通过放宽阈值、隐藏重试或接受非物理点来宣布成功。

## 历史证据与当前证据的区别

历史参考包 `offline_dual_reconstruction_v1_20261014` 的源码身份为 `bcf197d198d6e9ff2aef2d2dd7abfb6a025cb3f06df4739beb1a4d4190dc3dfd`，在当时同一工作站上曾完成四份私有录制。当前候选为解决发布与离线依赖问题，包含 7 个修改文件、2 个新增文件和三份冻结的原生质量 DLL。因此：

- 历史四录制成功仍是历史参考证据；
- 当前候选必须重新通过四录制冷启动；
- 当前失败不能被历史结果覆盖；
- 当前候选也不能在未通过前继承“已验收”标签。

1. 用一般化的回访约束或等价根因修复解决 RA-012，不针对箱子或单一视频硬编码；
2. 增加能复现退化图并阻止回归的自动测试；
3. 从四份原始录制第一步开始，在四个全新输出目录中顺序运行，不复用历史中间产物；
4. 四份录制均达到 `dual_target_outputs_complete`；
5. 每份录制的 3DGS 与 PGSR 使用同一轮相机和尺度；
6. 实际打开并检查八个新预览的加载、旋转、平移、缩放、自由飞行和采集路径；

8. 在干净克隆中再次通过发布内容验证。
