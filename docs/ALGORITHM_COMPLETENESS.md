# 算法完整性说明

## 完整性的定义

本发布候选把“算法完整”定义为：能够追溯正式双分支入口涉及的项目代码、历史兼容实现、审计/回归工具、目标几何子包、固定的第三方版本，以及相对于历史参考包和上游 PGSR 的本地修改。它不等于把操作系统、CUDA、Python 环境、训练数据和模型输出一并提交到 Git，也不等于当前候选已经通过端到端验收。

## 已保留

1. 历史参考包的完整 `payload/02_code` 源码树，以及当前候选的 13 个声明修改文件和 7 个新增文件；排除 Python 字节码缓存和机器专属 `OFFLINE_RUNTIME.local.json`。
2. `e26_video_to_target_m3_nollm_v1r23_20260927_installed_candidate` 的代码、配置、合同、几何模块、脚本、测试和第三方通知。
3. 历史参考包的正式入口、预检、绑定和包规范原文，放在 `docs/accepted_package/` 供追溯；它们不作为当前候选通过的证据。
4. PGSR 基线提交 `de24f1a38b350387e8d8fe381b2cd70c1ae946e7` 上的四文件补丁，包括新增的 `utils/projective_validity.py`。
5. 3DGS、gsplat、PGSR 的版本、提交和许可记录。
6. 初始选帧阶段需要的三份离线原生质量 DLL，以及记录源码、编译平台、文件身份和行为等价检查的运行时清单。

完整源码快照还保留了四个未被正式入口引用的 `optimization_v3` 研究期脚本；它们在历史参考包中就存在缩进、残留 JSON 或参数语法错误。为了保留来源，本候选没有静默修改或删除它们。验证器将这四项作为已知非生产遗留明确告警，并继续要求其余 Python 文件全部通过 AST 解析。详情见 `docs/PACKAGING_FAILURE_LEDGER.md`。

## 有意排除

- 原始 MCAP、抽帧图像、相机数据库和私有标定；
- 训练检查点、PLY/网格结果和四次验收预览；
- Windows 虚拟环境、COLMAP/CUDA 二进制、WSL 发行版和浏览器运行时；
- `__pycache__`、`.pyc` 和其他可再生成缓存；
- 包内运行证据、安装回执、进程信息和机器专属运行时配置，包括嵌套子包的 `config/local_runtime.json`；对应的 `runtime.example.json` 继续保留；
- 3DGS/PGSR/gsplat 的完整第三方源码副本。它们通过固定提交、许可和补丁复现。

这些排除项不会改变项目算法逻辑，但会影响“克隆后立即运行”。因此仓库的源码完整性与跨机器可运行性必须分开报告。

## 正式入口

历史参考包的生产入口为 `RUN.ps1`，最终调用：

`payload/02_code/reconstruction_dual_v1_20261009/run_target_delivery.py`

`docs/accepted_package/RUN.ps1` 是该入口的原始副本。它依赖同机目录连接，不应在未完成运行时重绑定时直接执行。

## 身份核验

`PUBLICATION_MANIFEST.json` 对本候选的每个发布文件记录 SHA-256，并给出当前算法源码树身份。`provenance/SOURCE_COPY_MAP.json` 记录历史参考包与当前候选的逐文件关系；`provenance/BASELINE_DELTA.json` 明确列出允许的 13 个修改文件和 7 个新增文件。验证脚本会检查：

- 清单是否完整且无多余文件；
- 源码是否等于历史参考包加上声明的精确差异，且没有未声明修改；
- 是否误带数据、模型、缓存、目录连接或常见凭据；
- PGSR 补丁和第三方许可是否存在。
- Python 文件是否被实际枚举；四个已知非生产研究遗留必须被单独披露，任何新增语法错误均失败。

## 不能据此声称的内容

- 公开数据集上的精度超过某一基线；
- 跨机器一键安装已经完成；
- 对任意物体和任意传感器格式均可泛化；
- PGSR 采样点等同于真实 LiDAR 原始测量；
- 历史四份私有录制的完成等同于当前候选四视频通过；
- 四份私有录制的视觉通过等同于独立 GT 几何精度证明。

当前端到端状态及升级为稳定版的必要条件见 `docs/VALIDATION_STATUS.md`。
