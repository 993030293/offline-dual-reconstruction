# 发布候选构建失败记录

本文件记录 GitHub 发布候选准备期间出现的原生失败。它们不属于四录制算法运行失败，也不能据此证明或否定重建质量；保留它们是为了避免把人工修复后的结果描述成“一次成功”。

| 顺序 | 阶段 | 原生失败 | 根因 | 修复与复核 | 对算法的影响 |
|---|---|---|---|---|---|
| 1 | 源码清单生成 | Python 在深层目标几何源码路径上报 `WinError 3`，清单未生成 | Windows 传统路径长度限制，读取深层目录失败 | 清单和验证工具改用 `\\?\` 扩展长度路径；随后完整读取并生成清单 | 无；仅影响发布验证工具 |
| 2 | PGSR 补丁回放封装 | 第一次命令未进入补丁检查，Windows 路径传入 WSL 时反斜杠丢失 | PowerShell 到 WSL 的路径转换/参数封装错误 | 增加独立 `tools/verify_pgsr_patch.sh`，使用明确 `/mnt/c/...` 路径 | 无；活跃 PGSR 源码未被修改 |
| 3 | PGSR 补丁格式 | `git apply --check` 报 `corrupt patch at line 120` | 新增文件实际 18 行，补丁 hunk 头误写为 19 行 | 修正为 `+1,18`，再次从固定基线回放 | 无；修复的是发布补丁文本 |
| 4 | PGSR 风格检查 | 补丁可应用，但 `git diff --check` 因一行尾随空格退出非零 | 活跃且已用于验收的 PGSR 修改保留了尾随空格 | 不擅自格式化已验收源码；改用补丁预检、语法检查和四个修改文件逐文件 SHA-256 相等作为身份验收 | 无；最终四文件与活跃运行时逐字节一致 |
| 5 | 全仓 Python 语法检查 | 首次独立命令返回成功，但报告 `PYTHON_AST_FILES=0` | 临时检查命令对 Windows 扩展长度根路径的枚举方式错误，属于空跑 | 不接受该结果；将 AST 解析并入已能完整枚举清单的发布验证器，并要求 Python 文件数大于零 | 无；仅修复验收覆盖 |
| 6 | 预发布清单复核 | 第一次重新生成清单后，验证器发现 42 个 `__pycache__`/`.pyc` 文件 | 本轮语法检查和预检产生了本地缓存，清单收集器没有像 Git 忽略规则一样排除它们 | 验证失败被保留；清单生成器和验证器都显式排除可再生成的 Python 缓存，再重新生成清单 | 无；缓存未暂存、未提交，也未进入算法输入 |
| 7 | 分量米制回归复跑 | 首次命令使用系统 Python，四个测试模块均因缺少 `pycolmap` 而无法导入 | 验收命令未绑定算法包自带的离线 Python 解释器 | 失败结果不计作测试结论；改用 `payload/05_envs/sfm_py311_v1/Scripts/python.exe` 重跑，47 项聚焦回归全部通过 | 无；属于验收环境选择错误 |
| 8 | 修改模块语法检查 | `py_compile` 尝试写入包内未保留的 `__pycache__` 目录并停止 | `py_compile` 本身需要落盘字节码，与本候选不保留缓存的约束不匹配 | 不创建或提交缓存；改用同一离线解释器的内存 AST 解析，4 个修改模块均通过 | 无；仅更换无写入的验收方式 |
| 9 | 当前克隆的完整离线预检 | 首次预检在读取 `OFFLINE_RUNTIME.local.json` 时立即停止 | 机器专属浏览器绑定被正确排除出 Git，但运行预检前尚未给这个克隆生成本地绑定 | 失败目录不复用；查询当前本机离线运行库，生成被 `.gitignore` 排除的本地绑定后在新目录重跑 | 无；暴露的是安装/绑定前置条件 |
| 10 | 当前克隆的浏览器真实启动 | 第二次预检显示 Playwright 期望未安装的 Chromium 1234，并且旧预检先因 GBK 文本解码失败而遮蔽原始诊断 | 当前 Codex 内置 Playwright 1.62.1 与本机已安装的离线 Chromium 修订不匹配；子进程又使用了系统默认文本解码 | 不下载任何内容；绑定本机已安装且与 Chromium 1208 匹配的 Playwright 1.58.2，并将预检改为二进制捕获后显式解码。第三个全新目录的完整离线预检通过 | 无；修复了运行时兼容绑定和失败可观测性 |
| 11 | 本地绑定后的发布清单复核 | 验证器返回通过，但文件数从 1648 增为 1649，且出现本机绑定的用户路径告警 | 清单生成器只在“源码差异”阶段排除 `OFFLINE_RUNTIME.local.json`，未在“发布文件枚举”阶段排除；验证器重复了同一缺口 | 该“通过”不接受；生成器和验证器共同按文件名排除机器绑定，并增加两个枚举器的回归测试后重新生成清单 | 无；避免了克隆后清单必然缺文件和本机路径暴露 |
| 12 | 提交前差异质量检查 | 清单内容与哈希均正确，但 `git diff --check` 将新增 JSON 行报为尾随空白 | 清单沿用仓库已有 CRLF 字节约定，但 `.gitattributes` 只声明了 `* -text`，没有让差异检查把行尾 CR 识别为合法换行 | 不接受全文转换造成的大量无意义差异；生成器改为显式可重现 CRLF，两份生成清单单独声明 `cr-at-eol`，并增加字节级换行回归 | 无；保留原有字节约定并消除无关差异 |

发布内容层面通过的检查包括：

- 发布候选私有仓库模式完整性验证；
- 从 PGSR 固定基线提交干净回放补丁；
- 四个 PGSR 修改文件与活跃验收运行时 SHA-256 完全相等；
- 修改文件 Python 语法检查。

公开仓库模式仍被机器专属绝对路径和项目许可未决主动阻断。这是发布边界，不应被描述为算法失败。

上述结果只证明私有 Git 仓库内容可被一致核验，不证明当前算法候选端到端通过。当前分量米制候选只完成同轮上游的有界开发诊断，四视频原始录制冷启动完成数仍为 0/4；视频算法异常及当前边界见 `docs/VALIDATION_STATUS.md`。两类失败必须分开报告。
